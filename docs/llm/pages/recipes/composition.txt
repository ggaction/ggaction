# Composition Recipe

## Minimal flow

```javascript
import { chart, hconcat } from "ggaction";

const points = chart()
  .createCanvas({ width: 280, height: 220 })
  .createData({ values: pointRows })
  .createScatterPlot({ x: "x", y: "y" });

const bars = chart()
  .createCanvas({ width: 260, height: 220 })
  .createData({ values: barRows })
  .createBarPlot({ x: "category", y: "value" });

const dashboard = hconcat({
  programs: [
    { id: "main", program: points },
    { id: "detail", program: bars }
  ],
  gap: 20
});
```

`pointRows` and `barRows` are arrays of plain row objects containing the named
fields. Every child must already have one complete materialized Canvas.

## Follow a chart's results with an overlay

`createOverlay` adds a separately editable layer that follows another mark's final results.
For example, its line follows each bar's center and value endpoint after aggregation, binning,
grouping or stacking. Source edits update the overlay automatically through that explicit dependency.

Use `type: "point"` for points at those same result positions. The default `series: "source"`
keeps each source group; `series: "total"` follows the outer endpoints of stacked bars.
To connect scatterplot results, supply an explicit `orderBy: "x"` or `"y"`.
Style the new layer with the usual `encodeColor`, `encodeSize`, `encodeStroke` and mark editors.
Field mappings use the current result items, including after source filters and within each facet.
Edit the source to change linked positions. `editOverlay({ target: "trend", follow: false })`
freezes the current geometry as an independent normalized plot snapshot; further source edits
no longer move it. Independent axis scales require explicit axis selection when creating guides.

The [runnable overlay example](https://ggaction.github.io/ggaction/examples/linked-overlay/) uses the same public program as
the primitive-equivalence and rendering tests.

## Pair a resource view with an analytical chart

Show a tree, treemap, partition, graph or flow beside a point chart that explains
its source measurements. Each child owns its data, marks, scales and guides.
The analytical axis and legend explain the point chart; the resource view keeps
its native layout, thickness and styles.

Copy the [resource comparison module](https://github.com/ggaction/ggaction/blob/5046dcc5e26ec9dfb5f6707951c3bb0fcd72e0cf/examples/program-composition/resource-comparison.js)
beside this browser module, set its `chart`/`hconcat` import to `from "ggaction"`,
and provide `<canvas id="chart"></canvas>`. The helper
builds both children from the same rows, including distinct numeric `1` and
string `"1"` keys. Run this complete example in an ES module with `ggaction`
available through your bundler or import map.

```javascript
import { render } from "ggaction";
import { createResourceComparison, reviseResourceComparison } from "./resource-comparison.js";

const comparison = createResourceComparison("tree");
const mapped = comparison.encodeColor({
  target: { childPath: ["analysis"], id: "values" },
  field: "alternative"
});
const scaled = mapped.editScale({
  target: { childPath: ["analysis"] },
  id: "measure", domain: [0, 20]
});
const revised = reviseResourceComparison(scaled, "tree");
render(revised, document.querySelector("#chart").getContext("2d"));
```

The field edit changes the point colors and legend. Doubling the analytical
scale domain moves the points and ticks without editing the tree. The revision
helper then doubles each measurement and calls `reviseData` with both explicit
child paths in one action. Both sources and their dependent graphics update
atomically. A source error in either child leaves the earlier program intact.
Equal row keys do not synchronize children automatically; a revision addressed
to one child changes only that child.

The same module accepts `treemap`, `partition-cartesian`, `partition-polar`,
`graph-nodes`, `sankey-dag` and `sankey-cyclic`. Their native positions, thickness,
color styles and labels follow their existing resource contracts. This recipe
does not create a resource-native field mapping or legend. See
[explicit action targets](../../../api/composition/editing/#target-one-view-one-mark-or-several-marks)
for selecting a view separately from an action's native mark or scale ID.

## You must decide

- Horizontal `hconcat` or vertical `vconcat`
- The ordered child programs
- Stable child IDs only when later replacement must address a slot

## The library infers

- Parent Canvas dimensions from the child Canvases, gap, and padding
- A white parent background and independent child clipping
- Deterministic namespaces for every child graphic

Use `editCompositionLayout` to revise gap, alignment, or padding. Use
`replaceCompositionChild` to replace one named slot without mutating the
earlier composition.
