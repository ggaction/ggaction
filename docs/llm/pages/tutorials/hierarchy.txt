# Hierarchy tutorial

A hierarchy describes parent-child meaning. A layout computes positions, and a plot draws those positions. Keeping these steps separate lets two views share the same source while using different layouts.

## Example with real data

`createWorldPopulationTreemap` builds this chart from real data. It receives the rows of `data/gapminder.json` (Gapminder).
Draw the returned program with `render` in a browser or `renderToPNG` in Node.

```javascript
import { chart } from "ggaction";

export const REGIONS = Object.freeze([
  "South Asia",
  "Europe & Central Asia",
  "Sub-Saharan Africa",
  "Americas",
  "East Asia & Pacific",
  "Middle East & North Africa"
]);
const COLORS = ["#f59e0b", "#3b82f6", "#10b981", "#ef4444", "#8b5cf6", "#ec4899"];

// Gapminder 2005 populations grouped by the dataset's six regional clusters.
export function populationRows(gapminder) {
  return gapminder
    .filter(row => row.year === 2005)
    .map(row => ({ region: REGIONS[row.cluster], country: row.country, population: row.pop }));
}

// Region cells are pale, country cells strong; labels name places, not raw counts.
function paint(rows, regionOpacity, countryOpacity) {
  return REGIONS.flatMap((region, index) => [
    { path: [region], fill: COLORS[index], opacity: regionOpacity },
    ...rows.filter(row => row.region === region)
      .map(row => ({ path: [region, row.country], fill: COLORS[index], opacity: countryOpacity }))
  ]);
}

function names(rows, minimumPopulation) {
  return [
    ...REGIONS.map(region => ({ path: [region], text: region })),
    ...rows.map(row => ({
      path: [row.region, row.country],
      text: row.population >= minimumPopulation ? row.country : ""
    }))
  ];
}

export function createWorldPopulationTreemap(gapminder) {
  const rows = populationRows(gapminder);
  return chart()
    .createCanvas({ width: 960, height: 600, margin: { top: 80, right: 20, bottom: 20, left: 20 } })
    .createData({ id: "population", values: rows })
    .createHierarchyData({ id: "regions", data: "population", groupFields: ["region", "country"], value: "population" })
    .layoutHierarchy({ id: "treemap", method: "treemap", options: { size: [920, 500], padding: 18, method: "squarify" } })
    .createTreemapPlot({
      cells: { stroke: "#ffffff", strokeWidth: 1.5, overrides: paint(rows, 0.2, 0.85) },
      labels: { fontSize: 11, fill: "#0f172a", overrides: names(rows, 40e6) }
    })
    .createTitle({
      text: "Where the world's people lived in 2005",
      subtitle: "62 Gapminder countries · rectangle area is population · grouped by region"
    });
}

export function createWorldPopulationSunburst(gapminder) {
  const rows = populationRows(gapminder);
  return chart()
    .createCanvas({ width: 760, height: 640, margin: { top: 80, right: 20, bottom: 20, left: 20 } })
    .createData({ id: "population", values: rows })
    .createHierarchyData({ id: "regions", data: "population", groupFields: ["region", "country"], value: "population" })
    .layoutHierarchy({ id: "partition", method: "partition" })
    .createCoordinate({ id: "rings", type: "polar" })
    .createPartitionPlot({
      layout: "partition",
      coordinate: "rings",
      rootVisible: false,
      innerRadius: 60,
      outerRadius: 260,
      padding: [1, 1],
      cells: { stroke: "#ffffff", strokeWidth: 1, overrides: paint(rows, 0.95, 0.6) },
      labels: { fontSize: 10, minArcLength: 30, overrides: names(rows, 60e6) }
    })
    .createTitle({
      text: "World population by region and country, 2005",
      subtitle: "Inner ring: region · outer ring: country · angle is population"
    });
}
```

## Run the maintained examples

Serve the repository over HTTP and open [the tree example](https://github.com/ggaction/ggaction/tree/d11f932ea5d6209defb7013d77c1176fb8ab750c/examples/tree-layouts) or [the treemap example](https://github.com/ggaction/ggaction/tree/d11f932ea5d6209defb7013d77c1176fb8ab750c/examples/treemap-layouts). Their canonical public programs are `examples/tree-layouts/program.js` and `examples/treemap-layouts/program.js`; the same functions produce the images and test fixtures on this page.

Use the Getting Started browser module setup with a canvas whose id is `chart`. This is the complete vertical tree program:

Each program uses the same ordered action flow: `createCanvas`, `createData`, `createHierarchyData`, `layoutHierarchy`, then `createTreePlot` or `createTreemapPlot`, and `createTitle` for the heading. Explicit IDs bind the source, hierarchy and layout. Colors and text target typed node keys so a layout change cannot transfer a style to a different node.

## Change geometry while retaining meaning

Continue from `vertical` above with `vertical.editLayout({target:"layout", options:{siblingGap:150}})` to widen sibling spacing. Use `order:{by:"value",direction:"descending"}` in a subsequent layout edit to sort siblings by value. Each call rematerializes the dependent plot and leaves the original program unchanged.

Tree orientation is explicit. The radial variant additionally supplies radius, start angle and sweep. Angles are degrees clockwise from the top. Canvas changes move the stored layout into its plot frame; they do not rerun the hierarchy algorithm.

## Compare rectangle layouts

Slice-dice alternates subdivision directions. Squarify chooses rows to reduce extreme aspect ratios. Both preserve the hierarchy's values and typed node identities. Padding reserves space around children and permits internal labels; an internal label has zero opacity when no padding band remains.

## Edit data and remove views

Use `reviseData` for source values or `editHierarchyData` for hierarchy input policy. Both update the full dependent layout and plot closure. Unknown parents or invalid values reject the revision, leaving the earlier program and trace intact.

Removing a mark keeps its reusable layout. Remove the layout before its hierarchy, and remove the hierarchy before its source dataset. Shared or authored dependents are never silently discarded. See [Hierarchy resources and plots](../../../api/hierarchy/) for complete signatures, defaults, grouped and nested source forms, labels, sorting and removal rules.
