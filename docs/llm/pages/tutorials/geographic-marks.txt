# Draw geometry on a map

A geometry resource preserves source features. A projection maps their coordinates,
and one Geo coordinate shares that projection among shapes, points and lines.
This example uses local planar coordinates, so an identity projection preserves
the district outline, its courtyard, the three stops and their service route.

## Example with real data

`createWorldGdpMap` builds this chart from real data. It receives the parsed GeoJSON of `data/showcase/countries-110m.geojson` (Natural Earth, public domain).
Draw the returned program with `render` in a browser or `renderToPNG` in Node.

```javascript
import { chart } from "ggaction";

// Natural Earth 1:110m countries carry 2019 population and GDP estimates.
// Antarctica has no resident population, so it is left out of the map.
export function createWorldGdpMap(countries) {
  const inhabited = {
    type: "FeatureCollection",
    features: countries.features.filter(feature => feature.properties.CONTINENT !== "Antarctica")
  };
  const economy = inhabited.features.map(feature => {
    const { ADM0_A3, NAME, POP_EST, GDP_MD } = feature.properties;
    return {
      code: ADM0_A3,
      name: NAME,
      gdpPerPerson: POP_EST > 0 && GDP_MD > 0 ? (GDP_MD * 1e6) / POP_EST : null
    };
  });

  return chart()
    .createCanvas({
      width: 960,
      height: 540,
      margin: { top: 70, right: 30, bottom: 30, left: 30 }
    })
    .createGeometryData({
      id: "countries",
      format: "geojson",
      coordinateKind: "geographic",
      polygonWinding: "left-hand",
      values: inhabited
    })
    .createData({ id: "economy", keyField: "code", values: economy })
    .createGeoJoinData({
      id: "country-economy",
      geometry: "countries",
      data: "economy",
      geometryKey: ["properties", "ADM0_A3"],
      dataKey: "code"
    })
    // Projected coordinates are Canvas pixels, so fit the whole Canvas and pad it.
    .createProjection({
      id: "world",
      type: "equal-earth",
      fit: { geometry: "countries", width: 960, height: 540, padding: 50 }
    })
    .createCoordinate({ id: "map", type: "geo", projection: "world" })
    .createGraticule({
      coordinate: "map",
      extentDeg: [[-180, -60], [180, 85]],
      stepDeg: [30, 30],
      stroke: "#e2e8f0",
      strokeWidth: 0.6
    })
    .createGeoShapeMark({
      id: "countries-shape",
      geometry: "country-economy",
      coordinate: "map",
      stroke: "#ffffff",
      strokeWidth: 0.5,
      // A whole-world outline exceeds the default 10,000 projected points.
      capacity: { maxProjectedPoints: 40000, maxPathCommands: 60000 }
    })
    .encodeColor({
      target: "countries-shape",
      field: "gdpPerPerson",
      fieldType: "quantitative",
      scale: {
        type: "threshold",
        domain: [2000, 5000, 10000, 25000, 50000],
        range: ["#fde68a", "#fbbf24", "#f59e0b", "#d97706", "#b45309", "#78350f"]
      }
    })
    .createLegend({
      target: "countries-shape",
      channels: ["color"],
      title: "GDP per person (USD)",
      position: "bottom-left"
    })
    .createTitle({
      text: "GDP per person, 2019",
      subtitle: "Natural Earth country estimates · equal-earth projection"
    });
}
```

## Complete program

The Full package contains the geographic actions. This complete example declares
its own geometry and uses pixel radii for the stop symbols.

> **Runnable complete example.** Import the Full ggaction package; this example declares its own planar geometry.

```javascript
import { chart } from "ggaction";

const program = chart()
  .createCanvas({"width":640,"height":480,"margin":40})
  .createGeometryData({"id":"districts","format":"geojson","coordinateKind":"planar","featureKey":"id","values":{"type":"Feature","id":"district","properties":{"name":"District"},"geometry":{"type":"Polygon","coordinates":[[[80,90],[360,90],[360,370],[80,370],[80,90]],[[160,170],[160,290],[280,290],[280,170],[160,170]]]}}})
  .createGeometryData({"id":"stops","format":"geojson","coordinateKind":"planar","featureKey":"id","values":{"type":"FeatureCollection","features":[{"type":"Feature","id":0,"properties":{"name":"West"},"geometry":{"type":"Point","coordinates":[120,130]}},{"type":"Feature","id":1,"properties":{"name":"Central"},"geometry":{"type":"Point","coordinates":[400,220]}},{"type":"Feature","id":2,"properties":{"name":"East"},"geometry":{"type":"Point","coordinates":[520,330]}}]}})
  .createGeometryData({"id":"services","format":"geojson","coordinateKind":"planar","featureKey":"id","values":{"type":"Feature","id":"service","properties":{"name":"Service route"},"geometry":{"type":"LineString","coordinates":[[120,130],[400,220],[520,330]]}}})
  .createProjection({"id":"map","type":"identity"})
  .createCoordinate({"type":"geo"})
  .createGeoShapeMark({"geometry":"districts","fill":"#93c5fd","stroke":"#1e40af","strokeWidth":2})
  .createGeoLineMark({"geometry":"services","stroke":"#475569","strokeWidth":3})
  .createGeoPointMark({"geometry":"stops","fill":"#dc2626","radiusPx":8});
```

For longitude and latitude, choose a spherical projection instead of identity.
A graticule uses the same projection and coordinate binding as other geographic
marks. Its spacing and precision are explicit angular values.

Changing the projection updates every bound mark together. Pixel-sized points
keep their radius; an explicit radiusDeg represents a geographic disk whose
screen size changes with the projection. Feature selection keeps the original
feature key when a line splits at the date line or a feature moves out of view.

A feature with null geometry remains a source feature but has no graphic or hit
target. Polygon holes remain empty in Canvas, SVG, PNG, PDF and hit testing.
Use a projection fit when you want a stored geometry resource to determine scale
and translation; Canvas resizing alone does not silently fit the geometry.

See [Geometry and projections](../../../api/geometry/) for exact options, revisions,
selection, coordinate compatibility and current limitations. The
[shared example source](https://github.com/ggaction/ggaction/blob/c463cf422b0a1f4fa7d3c903525387ac393c3c09/examples/geographic-marks/program.js)
draws the small planar figures on this page.

## Keep labels attached to their features

The annotation variant of the shared example adds West, Central and East using each stop's typed
feature key. This module imports the shared example program shown above; keep its `program.js` and
`fixture.js` together in a `geographic-marks` folder. A negative `dy` places the text sixteen logical
pixels above its projected anchor.

> **Runnable complete example.** Copy the linked geographic-marks program.js and fixture.js into a geographic-marks folder beside this module.

```javascript
import { createGeographicMarks } from "./geographic-marks/program.js";

const labeled = createGeographicMarks()
  .createGeoAnnotation({ id: "west-label", anchor: { type: "feature", geometry: "stops", key: 0 },
    text: "West", dy: -16, align: "center", fontSize: 18, fill: "#0f172a" })
  .createGeoAnnotation({ id: "central-label", anchor: { type: "feature", geometry: "stops", key: 1 },
    text: "Central", dy: -16, align: "center", fontSize: 18, fill: "#0f172a" })
  .createGeoAnnotation({ id: "east-label", anchor: { type: "feature", geometry: "stops", key: 2 },
    text: "East", dy: -16, align: "center", fontSize: 18, fill: "#0f172a" });
```

The anchor follows the original feature when its geometry or projection changes. For an LOD source,
the annotation remembers the selected original level and key even while a coarser feature represents
it. Use a position anchor when the location is meaningful without a named feature. Empty text and
clipped anchors keep their semantic intent while producing no visible text.

## Map visitor counts to stop area

The field example uses the same planar
features with three stop counts, 1, 4 and 9. Their circle radii are 8, 16 and 24
pixels, so their areas have the same ratio as those counts. Native categorical
color scales distinguish the stops. The shared public program uses `createGeographicMarks("fields")`; it supplies its own measured features.

Use `encodeColor({ field, scale })` after a shape, point or line mark, and
`encodeSize({ field, scale })` after a point mark. `createLegend()` can add the
existing color and size blocks. A join exposes the matching table fields and
LOD exposes the active level. See [field mapping rules](../../../api/geometry/#map-feature-fields-to-color-and-size)
for unknown values, geographic radii and explicit constant transitions.

## Emphasize stops with conditions

The same public program's `createGeographicMarks("conditional")` variant keeps the
visitor-area mapping while drawing West gray, Central teal and East red. A
visitor count of at least eight matches the first color branch; a count of at
least four matches the second. The required `otherwise` supplies West's color.
Both color and size use the same original feature key, and their native scales
still inspect all eligible features. The exact executable conditions live in
that program's shared fixture. See [conditional feature mapping](../../../api/geometry/#choose-color-or-size-with-conditions)
for predicates, selections and legend ambiguity.

## Keep stops stable while navigating

The executable `createGeographicMarks("camera")` variant in the same example applies an anchored
0.75 zoom followed by a small pan. Its district and route move with the projection, while each
stop remains eight CSS pixels in radius. Use `navigateProjection` for these view changes; save
`getProjectionView(program).parameters` before navigation when you want an explicit reset target.
The [camera reference](../../../api/geometry/#navigateprojection) lists pinch, fit and resize options.

## Label feature fields and graticules

Use `createGeographicMarks("labels")` from the same shared example module for one
Text label layer reading each stop's `name`. Its `createMarkLabels` call selects
`source: "geo-point"`, applies an eighteen-pixel font and a negative sixteen-pixel
vertical offset. This produces the same West, Central and East labels as the fixed
annotation example, with content now read from the source features.

The `createGeographicMarks("grid-labels")` variant labels the existing graticule's
`value` field with `format: ".0f"`. Its inline selector chooses `axis: "longitude"`,
so only −40, 0 and 40 appear above the meridian centroids. Both variants preserve
source feature identity through projection edits and reuse the native Text
style, font and collision-layout actions. See [geographic label rules](../../../api/marks/labels/#geographic-sources).

## Compare graticule degrees in a companion chart

Read each graticule item's raw `axis` and numeric `value` with `getMarkItems`.
An explicit analytical child can map those values to positions, colors, an axis
and a legend. These guides describe that child: they do not turn the graticule's
projection geometry into Cartesian field encodings or scales.

Copy [comparison.js](https://github.com/ggaction/ggaction/blob/c463cf422b0a1f4fa7d3c903525387ac393c3c09/examples/geographic-marks/comparison.js),
[program.js](https://github.com/ggaction/ggaction/blob/c463cf422b0a1f4fa7d3c903525387ac393c3c09/examples/geographic-marks/program.js)
and [fixture.js](https://github.com/ggaction/ggaction/blob/c463cf422b0a1f4fa7d3c903525387ac393c3c09/examples/geographic-marks/fixture.js)
into a `geographic-marks` folder beside this module, using the helpers' public
`ggaction` and `ggaction/inspection` imports.

> **Runnable complete example.** Copy geographic-marks/comparison.js, program.js and fixture.js beside this module and use their public package imports. The helper explicitly snapshots raw axis and numeric degree values.

```javascript
import { createGraticuleComparison, refreshGraticuleComparison } from './geographic-marks/comparison.js';
import { renderToSVG } from 'ggaction/svg';

const comparison = createGraticuleComparison();
const analytical = comparison
  .encodeColor({ target: { childPath: ['analysis'], id: 'values' }, field: 'sign' })
  .editScale({ target: { childPath: ['analysis'] }, id: 'degrees', domain: [-80, 80] });
const changedGrid = analytical
  .editProjection({ target: { childPath: ['grid'], id: 'map' }, translatePx: [325, 247] })
  .editGraticule({ target: { childPath: ['grid'], id: 'graticule' }, stepDeg: [20, 20] });
const refreshed = refreshGraticuleComparison(changedGrid);
const svg = renderToSVG(refreshed);
```

The initial six items contain longitudes −40, 0, 40 and latitudes −20, 0, 20.
The step edit adds longitudes −20 and 20. Projection movement preserves these
raw degree values and their native keys. Analytical edits leave the grid child
unchanged; grid edits leave the analytical snapshot unchanged until the explicit
refresh. That refresh calls `getMarkItems` again and `reviseData` on the analytical
child. Its new dataset rows are an explicit snapshot, not an invented geographic
source-row reference or an automatic live link.
