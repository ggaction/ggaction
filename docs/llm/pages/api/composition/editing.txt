# Editing Compositions

[Family overview](../../../../api/composition/) · [Exact action lookup](../../../../reference/actions/)

## Add an adjacent chart and share scales

Call `createAdjacentPlot` on a complete chart to add a new view to its left, right,
top or bottom. By default it creates a line using the source fields and aggregation.
Supply `plot: { action: "createScatterPlot", options: { x: "month", y: "sales" } }`
(or another native constructor) to select a different chart. All native constructor families can infer their source data and unambiguous positional
roles, including original fields behind statistical plots. Supply native options
for any role that cannot be inferred, such as a second Dumbbell measure. The new chart
has independent data and appearance; use `createOverlay` when it should follow results.

The selected source mark's ID names the original view; the new `id` names both the
adjacent view and its initial mark. Nested concats use explicit child paths when adding
another view. A facet is one editable source view; generated cells remain derived.

To attach one wide chart below an entire row (or a tall chart beside a column),
select the concat itself as the receiver. Its original composition ID names the
preserved group inside the new parent. A concat requires an explicit structured
`source: { childPath, id }`; the source path is **relative to the receiving group**.
It identifies the unit or facet supplying data and defaults, independently of where
the new chart is attached. Overlays and generated facet cells cannot be sources.

> **Executable complete.** Import chart from ggaction. This complete example includes all data and adds a full-width line below an existing pair using an explicit source panel.

```javascript
import { chart } from "ggaction";

const values = [{ month: 1, sales: 20 }, { month: 2, sales: 35 }];
const bars = chart().createCanvas({ plot: { width: 240, height: 220 }, margin: 80 })
  .createData({ id: "sales", values })
  .createBarPlot({ id: "bars", x: "month", y: "sales" });
const pair = bars.createAdjacentPlot({ id: "line", source: "bars", position: "right" });
const withWideBottom = pair.createAdjacentPlot({
  id: "bottom",
  source: { childPath: ["bars"], id: "bars" },
  position: "bottom",
  plot: { action: "createLinePlot", options: { x: "month", y: "sales" } },
  share: { x: true },
  align: "plot"
});
```

Top/bottom additions span the receiving group's plot-union width; left/right
additions span its plot-union height. The other dimension comes from the explicit
source view. This changes plot geometry without stretching text or symbols.
To attach to an inner group, set `target: { childPath: ["group"] }` and provide a
source path relative to that group. Existing group titles remain local to it.
The new chart ID must differ from the preserved group's composition ID.

Horizontal placement defaults to shared Y and vertical placement to shared X.
Explicit `share` replaces that default. `hconcat` and `vconcat` also accept `share`.
Shared channels must use compatible fields, measurement units and scale mappings.
Conflicting explicit domains reject the whole operation. Automatically inferred domains
are combined afresh after each edit, so they can grow and shrink. Authored child domains
are preserved: `editCompositionScales({ share: { y: false } })` restores independent Y.
A shared palette change must target all affected views in the same atomic call.
For a faceted child, sharing uses the union of the displayed cell domains after
partitioning, aggregation and stacking, rather than the unpartitioned source's
domain. The resulting domain applies to every cell and adjacent view, including
cells whose facet scale policy was independent. Disabling the outer sharing
restores the facet's original scale policies and inferred domains.

`align: "plot"` aligns both ends of the shared-axis plot frames. It rematerializes
render snapshots at a common plot extent while preserving child margins and authored
sizes. This also works with nested concat and facet views. Text and symbols keep their
sizes. The existing start, center and end Canvas alignment modes are unchanged.

## Target one view, one mark, or several marks

A native action accepts `target: { childPath: ["bars"], id: "trend" }` to edit the
trend mark in the bars view. Omit `id` for a view-level operation such as `createTitle`.
An empty child path refers to the current view. A nonempty array of selectors applies
the same native action atomically to every listed target. In a unit chart, an array of
mark IDs is sufficient. This is one public action and one root trace entry.

An All control should enumerate the explicit compatible targets. No wildcard silently
changes unrelated marks. A linked overlay follows source positions; edit its source
for geometry and target the overlay for independent appearance. Generated facet cells
are not persistent edit targets: select the facet view and use `editFacetSource`.
The Basic entry point and low-level primitives retain their original target contracts.

## Edit the layout

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `row`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const revised = row.editCompositionLayout({
  gap: 28,
  align: "start",
  padding: { left: 12, right: 12 }
});
```

This continuation edits the `row` concat created above. For a one-field facet,
use its own retained parent to change the number of columns:

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `faceted`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const twoColumns = faceted.editCompositionLayout({ columns: 2, gap: 28 });
```

At least one option is required. Omitted values retain their current settings;
a partial padding object updates only the named sides. A facet gap pair always
requires both `x` and `y` and replaces the complete pair; `gap: 28` resets both
directions to the same distance. Concat gaps remain numbers. The action preserves all
child IDs and references and rebuilds the parent snapshot.

Facet parents use this same action for `gap`, `align`, and `padding`; derived
cell programs and facet value order remain unchanged. One-field facets and
field repeats also accept `columns`. A row-column grid keeps its declared
column-domain width, and concat compositions reject `columns`. Parent-title and
header anchors are recomputed from the newly translated child plot bounds.

## Edit facet scale and guide policies

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `faceted`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const independent = faceted.editFacetScales({
  x: "independent"
});

const outer = independent.editFacetGuides({
  axes: "outer",
  legend: "shared"
});
```

Both actions preserve the facet field, source data, first-appearance value
order, child IDs, layout, headers, and title. Omitted policies retain their
current values. Scale edits require an effective change on a channel used by
the repeated chart.

For Polar and Parallel facets, use `theta`, public `r`, or
`parallelDimensions`. Their axes remain per panel, so `axes: "outer"` is
rejected at creation and during guide editing.

Policy edits immutably rederive every cell from the retained pre-facet program.
This reruns supported statistical descendants, histogram binning, scale
resolution, marks, guides, selections, and highlights instead of modifying a
filtered child in place. A shared legend is promoted only when every child has
a concretely compatible scale and guide recipe; otherwise the entire edit is
rejected and the earlier facet remains unchanged.

`facetGrid` and `repeatCharts` use these same editing actions. Empty full-grid
cells stay blank during scale and guide edits. A repeated positional channel
still rejects `axes: "outer"`.

## Replace the repeated source recipe

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `matrix`. Resource selectors used here: `target: "plot"`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const revised = matrix.editFacetSource({ program: revisedUnit });
const styled = matrix.editFacetSource({
  action: { method: "encodeOpacity", options: { target: "plot", value: 0.6 } }
});
```

`editFacetSource` reapplies the stored facet, grid, or repeat recipe to a new
complete unit program. Alternatively, `action: { method, options? }` invokes one
public unit chart-authoring function against the retained full-data source before
rederiving every panel. Specify exactly one input form. Source edits retain new
label and statistical-reference recipes; they do not edit just one filtered cell.
Primitive, materialization, and composition actions are rejected.

It preserves layout, scale and guide policies, header
style, parent title, and stable child IDs. The revised unit must still contain
the stored partition dataset and fields or repeated target role, and every
stored ordered value must remain observed. To change a partition dataset ID,
facet domain, or repeat field list, create a new composition from the revised
unit with the desired recipe.

Composition Canvas dimensions are inferred from the child Canvases. To resize
every facet or repeat cell, call `editCanvas` on the revised complete unit and
pass that unit to `editFacetSource`; `editCanvas` itself accepts unit programs.

The call is atomic: an invalid new unit changes neither the existing parent nor
the caller-owned program.

## Replace one stable slot

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `revised`. Resource selectors used here: `target: "detail"`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const replaced = revised.replaceCompositionChild({
  target: "detail",
  program: donutChart
});
```

The replacement must be a complete unit or nested composition program. Its new
size participates in layout inference, while the target ID and position in the
ordered child list remain stable. Earlier parent and child programs are not
mutated.

Facet cells are derived from one canonical source and cannot be replaced with
`replaceCompositionChild`.

## Insert, remove, and reorder named concat children

> **Contextual fragment.** Use an ES module with the imports, data, and prepared resource state described in this section. Caller-provided receivers: `row`. Resource selectors used here: `target: "detail"`. Resolve these names from setup in this fragment or section; alternatives branch from the same base.

```javascript
const expanded = row.insertCompositionChild({
  id: "forecast",
  program: forecastChart,
  after: "detail"
});

const reordered = expanded.reorderCompositionChildren({
  order: ["forecast", "main", "detail"]
});

const compact = reordered.removeCompositionChild({ target: "detail" });
```

Insertion accepts either `before` or `after`; with neither it appends. IDs and
anchors must be known and unique. Reordering requires every current child ID
exactly once. Removal may leave a valid one-child concat, but cannot remove the
last child. Each successful edit preserves retained child references and
rematerializes geometry from the new order. Failed edits leave the earlier
composition untouched.

These structural actions and `replaceCompositionChild` apply only to concat
parents. Facet-derived children remain governed by their canonical recipe and
the facet-specific edit actions.

For Cartesian facets, `editFacetGuides({ axes: { x: "outer" } })` changes only the X policy;
the Y policy stays unchanged. Scalar `"each"` or `"outer"` changes both channels. At creation,
omitted object channels default to `"each"`. Empty or unknown channel policies are rejected.
Wrapped layouts can switch to `editCompositionLayout({ spacing: "content" })` to pack native
content bounds independently; keyed grids reject this mode. Reset `topLane` to `"stacked"`
in the same call when switching from a shared plot lane. Header `anchor: "view"` includes
retained guides in its outward clearance and is available with plot or content spacing.

When color is shared, compatible same-field color/shape legends and color-only legends
are collected into one legend, retaining its authored position, alignment and typography.
A new adjacent chart with shared color retains the existing legend presentation rather than
resetting it to the right. Edit the contributing child legends with explicit targets to change
the collected block; its occupied bounds participate in the parent Canvas and plot layout.
The combined symbols retain their shape meaning;
unrelated size legends and conflicting shape mappings remain separate. Disabling color
sharing restores the original child legends, including in nested and faceted views.

## Layer a native chart

Use `createLayerPlot` for independently computed plots over the same measurements:

> **Executable complete.** Self-contained deterministic observations with shared measurement scales and independent native layers.

```js
import { chart } from "ggaction";
import { getPlotComposition, describeAction } from "ggaction/inspection";
const data = Array.from({ length: 36 }, (_, i) => ({ group: i % 2 ? "A" : "B", value: 2 + i % 11 }));
const program = chart()
  .createCanvas({ plot: { width: 360, height: 300 }, margin: 90 })
  .createData({ values: data })
  .createBeeswarmPlot({ id: "observations", x: "group", y: "value" })
  .createLayerPlot({
    id: "summary",
    source: "observations",
    plot: { action: "createBoxPlot", options: {
      width: { band: 0.4 }, outliers: false, box: { opacity: 0.25 }
    } },
    placement: "back"
  })
  .createGuides();
const source = getPlotComposition(program, { target: "summary" });
// source.channels.y.field is "value", not the internal Q1 column.
const check = describeAction(program, { action: "createLayerPlot", options: {
  id: "samples", source: "summary", plot: { action: "createStripPlot" }
} });
```

The new plot shares coordinates and compatible scales, including the original
fields behind a statistical chart. Its appearance remains independently editable.
`placement: "back"` puts the entire compound plot behind existing marks.
Use native encodings and plot editors to adjust each layer. Shared scale edits
apply to every consumer. Color is inherited when available at the layer's grain.

Use `createOverlay` when a line or point should **follow the existing visible
results**, such as stacked bar endpoints. Use `createLayerPlot` for independent
observations/distributions, such as Beeswarm + Box or Violin + Box + Strip.
Different units or coordinates belong in an adjacent chart. In particular,
histogram counts, density and cumulative probability cannot share one height
scale. A Rug can reuse only their measurement axis.

Preflight uses constructor roles without rendering all candidates. Native
constructors still validate data-dependent conditions when invoked. Layering
inside a facet uses `editFacetSource`; inside a concat, use a scoped `target`.
