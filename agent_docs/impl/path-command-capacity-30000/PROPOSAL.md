## 문제와 증거

원본 1774는 26,265개 행을 보존하고 날짜를 분 단위로 자른 뒤 평균을
계산하여 25,909개 관측점을 만든다. 원본은 800×200 플롯, 845×247
바깥 크기, 0.2px 선이다. 기존 `createComputedData`의 숫자 변환,
`createTimeUnitData({ id: 'minute', field: 'date', unit: 'minute' })`,
`createSummaryData`의 평균까지 성공한다. `createLinePlot`에서
`Curve path command count must not exceed 20000.`로 실패한다.

원본 및 네이티브 재현 기록은 번역 작업공간의
`tmp/total1500-1774-current-preflight/source-only-preflight-v1.json`과
`native-capacity-probe-v1.json`이다. 원본 SHA256:
`d303043c94a32d7a5f465ae33e9b8d29d9de88ac1a698aa9446962bdc6f867eb`.
학교 모델 호출은 아직 0건이며 이 원본은 완료·입장 처리하지 않았다.

## 승인과 범위

사용자는 번역하면서 필요한 라이브러리·파이프라인 수정을 계속하도록
지시했고, 2026-10-20에 “지금까지 모든 질문, 앞으로 할 모든 질문 승인함.
새로운 릴리즈는 200개 단위로 하자”라고 명시했다. 같은 작업 범위의
자원 상한 수정 승인을 재사용한다. 별도 API, 액션, 저장 필드, 렌더링 방식,
시각 디자인을 도입하지 않는다. 기존 경로의 기하·색·모양은 그대로다.

## 구체적 결정

`src/grammar/pathCommands.js`의 공유 `MAX_PATH_COMMANDS`만
20,000에서 **30,000(포함)**으로 높인다. 명령 하나는 M/L/C/Z 하나다.
모든 경로 생성, 명시적 경로 검증, 저장 복원, 선·면적·극좌표 곡선은
기존 단일 소유자의 검증을 그대로 사용한다. 스텝·곡선 보간과 닫기 명령의
확장을 먼저 세고 할당 전 거부하는 동작도 유지한다. 30,001개는 실패한다.
행·점·그룹·다른 생성 항목·작업 예산은 바꾸지 않는다. 자동 축약, 샘플링,
여러 경로로 몰래 분할, 원본 행 수정은 없다.

기존 20,000 이하 프로그램 및 저장 내용은 바이트/의미가 바뀌지 않는다.
20,001~30,000개의 유효 경로가 새로 허용되며, 새 저장 내용을 이전 버전에서
읽을 때는 이전 자원 한도 오류가 날 수 있다. 타입 선언은 기존 배열 타입을
유지한다. 공개 문서·현재 계약·생성 LLM 문서의 숫자 한도를 동기화한다.

## 검증과 완료 기준

- 19,999/20,000/20,001과 29,999/30,000/30,001 경계를 검사한다.
- linear/step/bezier/monotone 및 area 닫기 확장 후 실제 명령 수를 검사한다.
- 큰 실제 선의 생성·편집·데이터 개정·축척 변경·저장 복원과 부모 불변성을
  검사한다. SVG/Canvas/PDF는 기존 concrete path를 소비하며 새 렌더러가 없다.
- 다른 생성 한도는 그대로임을 확인하고, 이전 작은 경로의 실제 좌표·순서를
  유지한다. 기존 20,000 상한을 가정하는 테스트는 새 상한의 초과를 검사한다.
- 정상 전체 테스트, 문서 생성·검증, 패키지 소비자 검사 후 후보 브랜치를
  커밋·푸시한다. 번역 런타임 도입에는 별도의 정확한 패키지/문서 바인딩과
  기존 전체 차트 호환 검증이 필요하다.
- 차트 이미지는 열거나 시각 검사하지 않는다. 수치/DOM/SVG 및 자동 렌더
  결과 검사로 검증한다. 배포·main 병합·Pages 갱신·이슈 종료는 다음 정규
  체크포인트(성공 원본 1,413개)까지 하지 않는다.
