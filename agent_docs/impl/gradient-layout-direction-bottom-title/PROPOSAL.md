# Independent gradient direction and optional bottom titles

Status: **ready-for-review; no implementation is approved or included**.

## Concrete evidence and scope

The visible blocking case is a continuous legend at the **right** of a150×150
plot, with an authored **horizontal120×16** color strip. Its actual frozen SVG
contains that horizontal rectangle and the visible black title `PP Score`.
The current public API derives strip direction from placement: right/left are
vertical, top/bottom horizontal. Creation and editing reject explicit direction.
Moving the group below the plot, replacing the continuous ramp with samples,
rotating the chart or drawing a manual primitive would change the design.

Two related sources author a vertical16×100 ramp with `Score` below the ramp.
Their frozen standalone CSS-variable title paint resolves to `none`: the DOM
retains the bottom title's bounds, but **there is no visible title ink**. They
are evidence of authored intent, not a claim of a visible bottom-title blocker;
those translations may continue if their actual first-render geometry is met.
Bottom titles are a separately reviewable related design choice.

`SOURCE_EVIDENCE.json` binds original source/data/compiled/SVG/contract bytes and
records actual SVG rectangles, title coordinates, paint and visibility. Paths
are losslessly encoded reference metadata. `EVIDENCE.json` is generated by:

```sh
node agent_docs/impl/gradient-layout-direction-bottom-title/REPRODUCE.mjs
```

The two-row public repro records accepted legacy right/top outputs, rejects both
new choices at creation and editing, checks SVG export and immutable parents,
and lists desired strip dimensions. It does not execute a proposed API or claim
an unimplemented rendered result. No chart pixels are inspected.

## Decision A: direction independent of placement

Extend existing `LegendOptions.direction` to continuous **gradient** legends:
`'horizontal' | 'vertical'`. No action or nested option is added.

```js
program.createLegend({
  position: 'right',
  direction: 'horizontal',
  gradient: { length: 120 }
});
```

This is a proposed fragment; the current runtime rejects it.

- `position` anchors the occupied group; `direction` orients its ramp, samples,
  ticks and labels. `gradient.length` follows the ramp, `thickness` crosses it.
- Omitted creation direction preserves today's rule exactly: right/left use
  vertical, top/bottom use horizontal. Existing output must remain byte-identical.
  Store explicit intent only when supplied; an implicit direction continues to
  follow placement. Editors preserve omitted explicit intent. A position-only
  edit of an implicit legacy group retains the existing position-derived rule.
- Horizontal ramps place labels below and increase values left-to-right; vertical
  ramps retain the current bottom-to-top value mapping. Reversed/log/sqrt/symlog
  domains and color interpolation keep their current numerical meaning.
  Vertical labels remain left of a left-edge group and right otherwise.
- Use existing public creation/aggregate guide entry points, whole legend editing,
  and `editLegendLayout`; do not introduce a renderer-only rotation or create a
  second scale. Representation switches preserve only applicable configuration;
  switching to sampled symbols retains their existing categorical layout rules.
- Support every already-supported gradient group placement and anchoring mode;
  this does not add positions. Existing native external offsets, side top alignment,
  group row/column/wrap packing and physical occupied bounds remain authoritative.
  A wide horizontal ramp at the right requires enough right Canvas margin.

## Decision B: a bottom gradient title

Separately extend `titlePosition` with `'bottom'` for gradient legends only.
Omitted remains `'top'`. Existing `'left'` behavior of other legend families is
unchanged; bottom is still rejected for categorical, sampled and size/opacity
families unless separately approved.

```js
program.createLegend({
  position: 'right',
  titlePosition: 'bottom',
  gradient: { length: 100 }
});
```

The bottom title follows the union of the ramp, ticks and occupied labels using
the existing native visible title gap12. It cannot overlap low-value labels.
Horizontal titles use the strip's center; vertical titles start at its left edge.
Multiline title lines retain their order and native spacing. `title:false` has no
occupied title; invisible paint is not invented, while existing layout semantics
remain consistent. No new gap, padding, rotation or title-alignment option is
proposed. Decisions A and B combine naturally but may be approved independently.

## Implementation plan after the relevant approval

Keep the current continuous-legend grammar/config/layout/materialization owners.
Synchronize creation and editing validators, selected block/group routing where
already supported, focused layout editor, TypeScript declarations, persistence
validation, current contracts, action metadata, public guides and generated docs.
Backend-neutral graphicSpec owns the resulting geometry; SVG/Canvas read it.
No macro-architecture or renderer-specific escape hatch is needed.

Every proposed edit validates an immutable speculative branch and commits
atomically. Invalid directions, unsupported title positions/families, insufficient
Canvas margins or guide collisions must leave the prior program and caller input
unchanged. Existing sampling, scale/data/Canvas/coordinate refresh, facets, theme
replay, group merging and save/import must retain explicit direction/title intent.
Legacy saved configurations load without a migration or altered default output.

## Required verification after approval

- Both directions at each existing gradient position; explicit-default and omitted
  legacy parity; position-only edits of implicit/explicit direction.
- Both title positions, multiline/hidden/empty-line titles and large fonts, body
  thickness/length, label offsets/formats and native gap/offset preservation.
- Reversed and transformed domains, all samples/color stops/opacity; no changes to
  underlying mark/data/scale semantics.
- Aggregate creation, direct creation, whole/focused editing, applicable block/group
  routing and representation switches; atomic negative cases and parent/input
  immutability.
- Concrete occupied-bounds and collision tests, multiple legend groups, top alignment,
  Canvas resize, scale/data refresh, facets, persistence/theme, SVG and Canvas parity.
- The visible source's actual120×16 horizontal strip stays at the right without
  moving its150×150 plot. Report the two CSS-variable sources' invisible text
  honestly and do not hold them solely for this optional bottom-title choice.

Only the affected visible horizontal-right case is held for Decision A. All other
translation work continues. Publishing an issue records the gap and proposal;
it does not approve implementation, package publication or deployment.
